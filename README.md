# Fictional finance workstation

The demo lets a person ask a Hermes agent about a fictional portfolio. Hermes calls four narrow tools, and Ternary Bonsai 2 27B supplies the explanation. The tools read holdings and analyst assumptions, compare feasible allocations against a written mandate, and save a review draft only when asked. No tool places trades or updates a real portfolio.

The [public reproduction guide](https://gist.github.com/ChaiWithJai/9d5cfd1583f66661a67ae5cca3801f8d) gives the command sequence. We captured both a direct Hermes run and a Slack DM through the existing A+ Client Commitments bot. Both read local CSV fixtures. Neither read a live Google Sheet.

The included data represents a fictional $1 million portfolio as of September 25, 2026. All asset names and report IDs begin with `FCT` or `FIC`. The local CSV files are the default source. A Google Sheets download is available when a user supplies a workbook and an OAuth token. The demo does not claim that the included fixture is a live Google Sheet.

## Data and method

Import [portfolio.csv](data/portfolio.csv) into a tab named `Portfolio`, and import [analyst_reports.csv](data/analyst_reports.csv) into a tab named `Analyst Reports`. Keep the header cells unchanged. A short title above the header is allowed; the reader finds the exact header within the first ten rows and converts formatted currency and percentages back to the CSV units. The [mandate](data/mandate.json) defines the allocation bounds, five percent search grid, maximum one way turnover, downside floor, scenario probabilities and scoring formula. The agent receives the exact source report ID, report date and confidence level with each assumption.

The current weights are 45 percent Harbor, 35 percent Orbit and 20 percent Reserve. The tool checks 20 feasible grid allocations. Under the fictional method, it selects 35 percent Harbor, 45 percent Orbit and 20 percent Reserve. The candidate raises the illustrative base scenario return from 7.75 to 8.65 percent and makes the downside scenario more negative, from negative 14.5 to negative 16.7 percent. A person must judge whether the tradeoff is acceptable. No realized returns or model forecasting skill are implied.

## Run locally

1. Start the matching Prism runtime with [start_model.sh](start_model.sh). Set `LLAMA_SERVER` and `BONSAI_MODEL` to local paths first. If another model server already occupies port 62737, reuse it after checking its model ID and parameters. The profile points directly to the local model endpoint on port 62737.
2. Run `python3 setup.py --profile finance-workstation` to create an isolated profile under `~/.hermes/profiles/`. The script refuses to replace an existing profile. Set `FINANCE_PYTHON` to a Python interpreter with MLflow installed when you want tool traces. Otherwise, tool tracing is disabled. Create a separate Slack app from [slack-manifest.json](slack-manifest.json), which was generated by Hermes and renamed for this demo. Add its bot and app tokens to the profile, and only authorize the demo users. The repository contains no Slack credentials and does not create an app by itself.
3. Run `hermes --profile finance-workstation chat --oneshot -Q -q "Read the fictional portfolio and analyst reports, compare the constrained scenarios, and explain the candidate's downside and source limitations."` to check the local agent before enabling Slack.
4. Send the same question to the Slack app. Then ask, "Save the candidate as a review draft for Alex." The draft stays in the local `drafts` directory, and the reply should say `pending_human_review` and `order_submitted: false`.

The Hermes profile uses a custom OpenAI compatible provider, a 65,536 token context, medium reasoning, eight turns, disabled memory and four explicit MCP tool schemas. The model launch uses one parallel slot, GPU offload, the Jinja template and a 512 token reasoning budget. These are reproduction settings, not a performance claim.

## Optional Google Sheets read

Set `FINANCE_SPREADSHEET_ID` and `FINANCE_GOOGLE_TOKEN`, then run `python3 sync_google_sheets.py`. Set `FINANCE_DATA_DIR` to the printed directory in the Hermes tool environment before starting the profile. The download reads the `Portfolio` and `Analyst Reports` tabs through the Google Sheets API, validates the rows, and records the workbook ID and sync time in `source.json`. The tool still reads a local snapshot, so the reply must show when that snapshot was downloaded. The script does not write to Sheets. The current [Hermes configuration](hermes-config.json) does not set `FINANCE_DATA_DIR`, so it uses the bundled fictional fixture until you add that value.

## Checks and evidence

Run `python3 -m unittest discover -s . -p 'test_*.py' -v`. The checks cover valuation and weights, scenario arithmetic, report provenance, constraint satisfaction, stale snapshot rejection, and proof that saving a draft does not alter holdings. Install `requirements-eval.txt` into a Python environment and run `python3 run_eval.py` while MLflow is available at the configured `MLFLOW_TRACKING_URI`. The MLflow run contains five deterministic checks and a candidate artifact.

One direct Hermes and Bonsai run used the three read tools and produced the expected scenario comparison. [The exported direct session](live-run-evidence.json) contains the prompt, tool names, tool outputs and final answer, excluding hidden reasoning and the system prompt. [Its MLflow run](http://127.0.0.1:5210/#/experiments/41/runs/e05c98815de04e799a35c92111fa07fa) records six narrow output checks. The run used four model API calls.

A second run came through a Slack DM to the existing Client Commitments bot, whose Hermes profile exposed this repository's finance MCP tools alongside its legal tools. [The Slack session](slack-live-evidence.json) records the prompt, tool calls, final answer, source hash and main-turn usage. [The screenshot of the allocation and reports](slack-allocation-review.jpg) and [the screenshot of its downside and source disclosure](slack-scenario-review.jpg) show the actual Slack reply, reframed to keep unrelated workspace content out of the image. [The MLflow run](http://127.0.0.1:5210/#/experiments/41/runs/0944b153dd22461796832768a3aba8a5) passed ten narrow checks against that one session. The model called the comparison tool twice with the same arguments, so the 101.5-second response has an avoidable extra tool turn. No draft or order tool ran.

[The measured call breakdown](PERFORMANCE.md) separates model latency from tool execution and defines a matched harness test for the duplicate call. It does not claim a speedup from the present evidence.

[Evidence notes](EVIDENCE.md) distinguish these observed runs from broader model reliability. The fixture is suitable for demonstrating the workflow, not for investment advice or an empirical alpha claim.
